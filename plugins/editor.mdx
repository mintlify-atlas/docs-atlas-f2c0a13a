## nvim-cmp (completion engine)

nvim-cmp is the completion engine that powers autocompletion from multiple sources including LSP, snippets, buffer text, and file paths.

### Configuration

```lua lua/leyland/plugins/nvim-cmp.lua
return {
  "hrsh7th/nvim-cmp",
  event = "InsertEnter",
  dependencies = {
    "hrsh7th/cmp-buffer",      -- source for text in buffer
    "hrsh7th/cmp-path",        -- source for file system paths
    "L3MON4D3/LuaSnip",        -- snippet engine
    "saadparwaiz1/cmp_luasnip", -- for autocompletion
    "rafamadriz/friendly-snippets", -- useful snippets
    "onsails/lspkind.nvim",    -- vs-code like pictograms
  },
}
```

### Completion sources

The completion engine pulls suggestions from multiple sources in priority order:

```lua
sources = cmp.config.sources({
  { name = "nvim_lsp" },  -- LSP completions (highest priority)
  { name = "luasnip" },   -- Snippet completions
  { name = "buffer" },    -- Text in current buffer
  { name = "path" },      -- File system paths
})
```

## LuaSnip (snippet engine)

LuaSnip provides snippet expansion and navigation, integrated with nvim-cmp for seamless completion.

### Features

- **Friendly snippets** - Pre-built snippets for many languages
- **Jump navigation** - Tab through snippet placeholders
- **VSCode compatibility** - Loads VSCode-style snippets

### Configuration

```lua
local luasnip = require("luasnip")

-- Load VSCode-style snippets from plugins
require("luasnip.loaders.from_vscode").lazy_load()

-- Configure snippet expansion
snippet = {
  expand = function(args)
    luasnip.lsp_expand(args.body)
  end,
}
```

### Usage

1. Start typing to trigger completion
2. Select a snippet from the completion menu
3. Press Tab to expand and jump to the next placeholder
4. Continue editing or press Tab again to jump forward

<Tip>
Snippets are context-aware and only show when appropriate for the current file type.
</Tip>

### Format on save

Files are automatically formatted when you save:

```lua lua/leyland/plugins/formatting.lua
format_on_save = {
  lsp_fallback = true,
  async = false,
  timeout_ms = 3000,
}
```

<Info>
If no formatter is configured, formatting falls back to LSP formatting if available.
</Info>

### Manual formatting

<ParamField path="<leader>mp" type="normal/visual">
  Format current file or selected range
</ParamField>

The manual format command is useful when you want to format without saving:

```lua
vim.keymap.set({ "n", "v" }, "<leader>mp", function()
  conform.format({
    lsp_fallback = true,
    async = false,
    timeout_ms = 1000,
  })
end, { desc = "Format file or range (in visual mode)" })
```

## nvim-autopairs

Automatically insert closing brackets, quotes, and other paired characters.

### Features

- **Treesitter integration** - Context-aware pairing based on syntax
- **Language-specific rules** - Custom behavior per language
- **Completion integration** - Works seamlessly with nvim-cmp

### Configuration

```lua lua/leyland/plugins/autopairs.lua
autopairs.setup({
  check_ts = true, -- enable treesitter
  ts_config = {
    lua = { "string" },              -- don't add pairs in lua strings
    javascript = { "template_string" }, -- don't add pairs in JS template strings
    java = false,                    -- don't check treesitter on java
  },
})
```

### Completion integration

Autopairs automatically triggers when confirming completions:

```lua
local cmp_autopairs = require("nvim-autopairs.completion.cmp")
local cmp = require("cmp")

cmp.event:on("confirm_done", cmp_autopairs.on_confirm_done())
```

<Tip>
Autopairs respects Treesitter context, so it won't add pairs inside strings or comments where they're not wanted.
</Tip>

## Workflow example

Here's how these plugins work together:

1. **Start typing** - nvim-cmp shows completions from LSP, snippets, and buffer
2. **Select completion** - Use Ctrl-j/k to navigate, Enter to confirm
3. **Expand snippet** - Tab through placeholders if it's a snippet
4. **Auto-pairing** - Brackets and quotes close automatically
5. **Syntax highlighting** - Treesitter colorizes code in real-time
6. **Format on save** - conform.nvim formats your code automatically

<CodeGroup>
```typescript Before
function greet({
// Start typing, completion triggers
```

```typescript After completion
function greet(name: string) {
  console.log(`Hello, ${name}`);
}
// Formatted, highlighted, and auto-paired!
```
</CodeGroup>

## snacks.nvim (smooth scrolling)

snacks.nvim is a collection of small quality-of-life improvements. In this configuration, it's used for smooth scrolling animations.

### Configuration

```lua lua/leyland/plugins/snacks.lua
return {
  "folke/snacks.nvim",
  priority = 1000,
  lazy = false,
  opts = {
    scroll = {
      enabled = true,
      animate = {
        duration = { step = 10, total = 100 },
        easing = "linear",
      },
    },
  },
}
```

### Features

<Card title="Smooth scrolling" icon="up-down">
  Animated scrolling when moving through files with Ctrl-d, Ctrl-u, or similar commands
</Card>

The animation makes it easier to track your position when jumping through code.

## trouble.nvim (diagnostics panel)

Trouble provides a beautiful panel for viewing LSP diagnostics, quickfix lists, and location lists.

### Configuration

```lua lua/leyland/plugins/trouble.lua
return {
  "folke/trouble.nvim",
  dependencies = { "nvim-tree/nvim-web-devicons" },
  opts = {},
  keys = {
    { "<leader>xx", "<cmd>Trouble diagnostics toggle<cr>", desc = "Toggle Trouble" },
  },
}
```

### Keybinding

<ParamField path="<leader>xx" type="normal">
  Toggle the Trouble diagnostics panel
</ParamField>

### Features

<CardGroup cols={2}>
  <Card title="LSP diagnostics" icon="stethoscope">
    View all errors, warnings, and hints in one place
  </Card>
  <Card title="Quick navigation" icon="location-arrow">
    Jump directly to any diagnostic location
  </Card>
  <Card title="Filtering" icon="filter">
    Filter by severity or file
  </Card>
  <Card title="Pretty formatting" icon="sparkles">
    Beautiful icons and colors for each diagnostic type
  </Card>

### Usage

1. Press `<leader>xx` to open the Trouble panel
2. Navigate through diagnostics with `j/k`
3. Press Enter to jump to the diagnostic location
4. Press `q` to close the panel

<Tip>
Trouble automatically updates as you fix issues in your code, giving you real-time feedback on your progress.
</Tip>

The LSP (Language Server Protocol) plugins provide intelligent code completion, diagnostics, go-to-definition, and more for multiple programming languages.

## Overview

The LSP setup consists of three main components:

## nvim-lspconfig

Provides the foundation for LSP integration by configuring language servers with proper capabilities.

### Configuration

```lua lua/leyland/plugins/lsp/lsp.lua
return {
  "hrsh7th/cmp-nvim-lsp",
  event = { "BufReadPre", "BufNewFile" },
  dependencies = {
    { "antosha417/nvim-lsp-file-operations", config = true },
    { "folke/lazydev.nvim", opts = {} },
  },
  config = function()
    local cmp_nvim_lsp = require("cmp_nvim_lsp")
    local capabilities = cmp_nvim_lsp.default_capabilities()

    vim.lsp.config("*", {
      capabilities = capabilities,
    })
  end,
}
```

### Capabilities

The config enables autocompletion for all LSP servers:

```lua
-- Get default capabilities from nvim-cmp
local capabilities = cmp_nvim_lsp.default_capabilities()

-- Apply to all language servers
vim.lsp.config("*", {
  capabilities = capabilities,
})
```

<Info>
Capabilities tell language servers what features the editor supports, like snippet expansion, completion item documentation, and resolve support.
</Info>

### File operations

The `nvim-lsp-file-operations` plugin enables file operations through the LSP:

```lua
{ "antosha417/nvim-lsp-file-operations", config = true }
```

This allows language servers to:
- Update imports when files are moved
- Rename references when files are renamed
- Clean up references when files are deleted

### lazydev.nvim

Provides enhanced Lua development specifically for Neovim:

```lua
{ "folke/lazydev.nvim", opts = {} }
```

<Accordion title="What lazydev provides">
  - **Neovim API completion** - Full autocomplete for `vim.*` APIs
  - **Plugin development** - Proper types for plugin development
  - **Runtime path awareness** - Understands Neovim's runtime structure
  - **No LSP restart needed** - Works immediately without restarting lua_ls
</Accordion>

## Mason (LSP installer)

Mason provides a UI for installing and managing language servers, formatters, and linters.

### Configuration

```lua lua/leyland/plugins/lsp/mason.lua
return {
  {
    "williamboman/mason-lspconfig.nvim",
    opts = {
      ensure_installed = {
        "ts_ls",
        "html",
        "cssls",
        "tailwindcss",
        "svelte",
        "lua_ls",
        "graphql",
        "emmet_ls",
        "prismals",
        "pyright",
        "eslint",
      },
    },
    dependencies = {
      {
        "williamboman/mason.nvim",
        opts = {
          ui = {
            icons = {
              package_installed = "✓",
              package_pending = "➜",
              package_uninstalled = "✗",
            },
          },
        },
      },
      "neovim/nvim-lspconfig",
    },
  },
}
```

## Adding new language servers

To add support for a new language:

<Steps>
  <Step title="Find the server">
    Check [Mason's registry](https://mason-registry.dev/registry/list) or run `:Mason` and search.
  </Step>
  <Step title="Add to ensure_installed">
    Edit `lua/leyland/plugins/lsp/mason.lua` and add the server name:

    ```lua
    ensure_installed = {
      "ts_ls",
      "lua_ls",
      "your-new-server",  -- Add here
    }
    ```
  </Step>
  <Step title="Restart Neovim">
    The server will be automatically installed on next startup.
  </Step>
  <Step title="Configure if needed">
    Most servers work automatically. For custom config, add to `lua/leyland/plugins/lsp/lsp.lua`:

    ```lua
    vim.lsp.config("your-new-server", {
      capabilities = capabilities,
      settings = {
        -- Server-specific settings
      },
    })
    ```
  </Step>
</Steps>

## Lua development with lazydev

For Neovim Lua development, lazydev provides superior completion:

<CodeGroup>
```lua Before lazydev
-- Generic Lua completion
vim.|  -- No API hints
```

```lua After lazydev
-- Full Neovim API completion
vim.lsp.|  -- Shows: config, buf, util, etc.
vim.api.nvim_|  -- Shows all nvim_ functions
require("telescope")|  -- Plugin-specific types
```
</CodeGroup>

<Tip>
lazydev automatically detects Neovim configuration files and plugin directories, providing appropriate completions without manual configuration.
</Tip>

## Troubleshooting

<AccordionGroup>
  <Accordion title="LSP not working">
    Check if the server is installed:

    ```vim
    :Mason
    # Look for checkmark (✓) next to server
    ```

    Check if LSP is attached:

    ```vim
    :LspInfo
    # Shows active servers for current buffer
    ```
  </Accordion>

  <Accordion title="Completions not showing">
    Verify nvim-cmp is configured:

    ```vim
    :CmpStatus
    # Should show nvim_lsp as a source
    ```

    Check LSP capabilities:

    ```vim
    :lua print(vim.inspect(vim.lsp.get_clients()[1].server_capabilities))
    ```
  </Accordion>

  <Accordion title="Server keeps crashing">
    Check server logs:

    ```vim
    :LspLog
    # Opens log file with error messages
    ```

    Try reinstalling:

    ```vim
    :Mason
    # Press X to uninstall, then i to reinstall
    ```
  </Accordion>

  <Accordion title="Slow completions">
    Some servers (like ts_ls in large projects) can be slow. Try:

    - Increase debounce time in nvim-cmp config
    - Use local tsserver: `npm install -g typescript-language-server`
    - Consider alternative servers like Deno LSP
  </Accordion>
</AccordionGroup>

## Performance

LSP plugins are optimized for performance:

- **Lazy loading** - Only load when opening files
- **Async operations** - LSP requests don't block the UI
- **Incremental updates** - Only changed regions are re-analyzed
- **Debouncing** - Diagnostics update after you stop typing

<Info>
Language servers run in separate processes, so they won't slow down Neovim's UI even when analyzing large codebases.
</Info>
